## ✨ What is ScholaAi?

ScholaAi is a **full-stack AI-powered online tutoring platform** that connects students with teachers for live, intelligent one-on-one sessions. The platform distinguishes itself through:

| Feature | Description |
|---|---|
| 🎥 **Live Video Sessions** | WebRTC-powered sessions via a dedicated mediasoup SFU server |
| 🧠 **AI Focus Detection** | Real-time student attention scoring using MediaPipe, OpenCV & DeepFace |
| 📝 **Auto Summarization** | Post-session lecture summaries generated by Whisper + LLaMA 3.3 (Groq) |
| 💬 **In-Session Chat** | Real-time messaging between teacher and student via SignalR |
| 💳 **Integrated Payments** | Stripe-powered wallet top-ups and per-session billing |
| ⭐ **Rating System** | Students rate teachers post-session; scores aggregate on profiles |
| 🔔 **Push Notifications** | Instant SignalR alerts for distractions, session requests & more |
| 🛡️ **Role-Based Access** | Three distinct roles: `Student`, `Teacher`, `Admin` |

## 🗂️ Domain Model

The database schema is managed via Entity Framework Core and centers around these core entities:

```
ApplicationUser (ASP.NET Identity)
    ├── Teacher ──────────────────────────────────────┐
    │       ├── Availability[]      (schedule slots)  │
    │       ├── Session[]           (hosted sessions) │
    │       └── Rating[]            (student reviews) │
    │                                                  │
    └── Student ─────────────────────────────────────┐│
            ├── SessionRequest[]   (booking requests) ││
            └── Rating[]           (given reviews)   ││
                                                      ││
Session ──────────────────────────────────────────────┘┘
    ├── ChatMessage[]    (in-session chat history)
    ├── Transaction      (billing record)
    └── Notification[]   (related alerts)

Wallet          (per-user balance, linked to Transaction[])
Subject         (platform-managed list of taught subjects)
AdminLog        (audit trail for admin actions)
```

## 🔔 SignalR Real-Time Hubs

The API exposes **three SignalR hubs** for real-time communication. Clients authenticate via the JWT token passed as the `access_token` query parameter during the WebSocket handshake.

### `/chatHub` — In-Session Chat

| Event | Direction | Payload | Description |
|---|---|---|---|
| `SendMessage` | Client → Server | `{ sessionId, message }` | Send a chat message |
| `NewMessage` | Server → Client | `{ sender, message, timestamp }` | Broadcast new message to session room |

---

### `/notificationHub` — Push Notifications

| Event | Direction | Description |
|---|---|---|
| `ReceiveNotification` | Server → Client | Delivers a new notification to the specific user |

---

### `/hub/session` — Session Events

| Event | Direction | Payload | Description |
|---|---|---|---|
| `JoinSession` | Client → Server | `{ sessionId }` | Join the session SignalR group |
| `LeaveSession` | Client → Server | `{ sessionId }` | Leave the session group |
| `StudentDistracted` | Server → Teacher | `{ studentName, focusScore }` | AI detected focus < 50% |
| `SessionEnded` | Server → Client | `{ sessionId }` | Teacher ended the session |
| `FocusUpdate` | Server → Teacher | `{ score }` | Real-time focus score relay |

## 🤖 AI Integration

ScholaAi integrates with two Python microservices from the **[ScholaAi-model-hub](https://github.com/<your-org>/ScholaAi-model-hub)** repository:

### Focus Detection Pipeline

```
Student Browser
     │  (webcam frames every ~500ms, base64 encoded)
     ▼
Focus Detector Service :8000   (MediaPipe + OpenCV + DeepFace)
     │  Computes score every 30s:
     │  • Eyes open     → 40 pts  (Eye Aspect Ratio)
     │  • Head centred  → 30 pts  (solvePnP head pose)
     │  • Positive mood → 30 pts  (DeepFace emotion)
     │
     ▼  POST /api/studentSessions/{id}/report-focus
ScholaAi .NET API
     │  Focus < 50%?
     ▼
SignalR Hub → Teacher Client: "StudentDistracted" event
```

### Post-Session Summarization Pipeline

```
Teacher ends session
     │
     ▼  Recording .webm uploaded to Supabase Storage
ScholaAi .NET API
     │  POST http://ai-server:8001/summarize
     ▼
Summarization Service :8001
     │  1. Whisper: audio → Arabic transcript
     │  2. Groq LLaMA 3.3 70B: transcript → structured Arabic summary
     │     (chunked for long sessions, then merged)
     ▼
ScholaAi .NET API  ←  { "summary": "## 📚 موضوع المحاضرة\n..." }
     │  Saves to session record in DB
     ▼
Student can read summary in "Past Sessions" page
```

## 💳 Payment Flow

ScholaAi uses a **wallet-based** payment model powered by Stripe:

```
1. Student tops up wallet
   └─► POST /api/payment/create-intent  (creates Stripe PaymentIntent)
   └─► Student confirms payment in browser (Stripe.js)
   └─► Stripe fires webhook → POST /api/payment/webhook
   └─► Backend credits wallet balance

2. Session is completed
   └─► Teacher ends session (POST /api/teacherSessions/end)
   └─► Backend deducts session fee from student wallet
   └─► 5 EGP platform fee is retained
   └─► Remainder transferred to teacher wallet
   └─► Transaction record created for both parties
```
